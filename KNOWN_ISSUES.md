## AeroChip: доступный невыбранный чип читается как отключённый (AeroBlue)

**Обнаружено:** 2026-07-29 (при миграции satellite-control на v3.0.0).
**Где:** `library/src/main/kotlin/com/mordred/aero/components/selection/AeroChip.kt`

**Не регрессия v3.0.** `AeroChip.kt` между тегами `v2.0.4` и `v3.0.0` не менялся,
токены `AeroBlue` тоже; кадры чипов из двух версий совпадают попиксельно. Дефект
существует как минимум с v2.0.4, просто раньше на него не смотрели.

Невыбранное состояние красится токенами темы:
```kotlin
targetValue = if (selected) colors.primary.copy(alpha = 0.25f)
              else colors.cardBackground.copy(alpha = 0.3f),   // строка 46, фон
targetValue = if (selected) colors.primary else colors.labelText,  // строка 58, текст
```
а отключённое отличается только полупрозрачностью поверх всего целиком:
```kotlin
.alpha(if (enabled) 1f else 0.4f)   // строка 65
```

В `AeroBlue` это даёт вырождение. `cardBackground = 0x40FFFFFF` — белый, поэтому
фон невыбранного чипа получается светло-серым, а текст `labelText = 0xFFBDBDBD`
тоже светло-серый: надпись тонет в заливке. Отключённый чип при этом гасится
до 40% альфы **вместе с заливкой**, и поверх тёмной подложки становится темнее —
то есть контрастнее доступного.

Измерено по скриншотам приложения ЦУС (WCAG 2.1, текст — 10% самых тёмных
пикселей, поэтому абсолютные значения занижены сглаживанием; важно соотношение):

| Чип | Состояние | Контраст |
|---|---|---|
| Калибр. | доступен | 1,41:1 |
| TLE | доступен | 1,36:1 |
| ВКИ | **отключён** | **1,62:1** |
| Краевая | выбран | 2,47:1 |

Инверсия налицо: доступное выглядит бледнее отключённого. Пользователь читает
активные типы расчётов как недоступные. Порог WCAG для обычного текста — 4,5:1,
ниже него здесь все состояния.

`AeroDark` и `Classic` затронуты слабее: там `cardBackground` тёмный, и заливка
невыбранного чипа не всплывает к цвету надписи.

**Направление фикса:** различать состояния не сплошной альфой поверх всего.
Варианты — гасить в отключённом состоянии только текст и рамку, оставляя заливку;
либо задать невыбранному чипу собственную заливку, выводимую от `background`,
а не от `cardBackground`; либо брать для надписи `onSurface` вместо `labelText`.
Любой вариант проверять на всех трёх схемах: правка, вытягивающая `AeroBlue`,
легко сажает `Classic`, где `cardBackground` непрозрачный.

## AeroDataTable: столбцы, стянутые в минимум, не разворачиваются обратно

**Обнаружено:** 2026-07-15 (при миграции satellite-control на v2.0.4).
**Где:** `library/src/main/kotlin/com/mordred/aero/components/datatable/AeroDataTable.kt`

`onColumnResize` накапливает сырую дельту перетаскивания без ограничения:
```kotlin
resizeOverridesPx[columnIndex] = current + deltaPx   // ~строка 167
```
Видимая ширина клампится позже, при вычислении `widthsDp` (`adjustedDp.coerceIn(minDp, maxDp)`, ~строка 137), но сам накопленный `override` не ограничивается. Если тянуть за минимум, `override` копит отрицательную «мёртвую зону»; при обратном движении её сначала надо выбрать, и только потом ширина начинает меняться. Несколько столбцов, стянутых в минимум, выглядят «застрявшими». `onColumnResizeEnd` (~строка 171) пуст — ренормализации нет.

**Направление фикса:** хранить кламп применённой ширины, а не сырую накопленную дельту; либо ограничивать `override` фактическим изменением видимой ширины.

## AeroDataTable: последний столбец / жёлоб скроллбара растягивается через заголовок

**Обнаружено:** 2026-07-15.
**Где:** `AeroDataTable.kt` + `datatable/internal/AeroTableHeader.kt`

Тело таблицы резервирует жёлоб под вертикальный скроллбар: `LazyColumn` c `.padding(end = 12.dp)` (~строка 204), рядом `AeroScrollBar` (CenterEnd). Но `availableWidthPx` (`BoxWithConstraints`, ~строка 115), ширины столбцов и заголовок (`AeroTableHeader`, полный `fillMaxWidth`) эти 12dp **не вычитают**. Дополнительно `AeroTableHeader` рисует resize-сплиттер на правом крае **каждого** столбца, включая последний (`AeroTableHeader.kt:129-148`).

Следствия:
1. Заголовок и тело рассинхронены по ширине на 12dp — при коротком списке жёлоб выглядит «лишним пустым столбцом» после последней колонки.
2. Сплиттер последнего столбца позволяет тащить его в зону скроллбара (резайзить нечего справа).

**Направление фикса:** вычитать ширину скроллбар-жёлоба из `availableWidthPx`/раскладки заголовка, чтобы заголовок и тело совпадали; не рисовать resize-сплиттер на правом крае последней колонки.
