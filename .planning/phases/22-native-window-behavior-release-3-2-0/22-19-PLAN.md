<objective>
API-04 / D-05 (ROADMAP Step 8, second half): promote the native wiring that Plans 07, 09 and 12 built for AeroTitleBar into a public, additive low-level API for apps with their own title bar, and rebuild AeroTitleBar on top of it.

D-05 proof choice (recorded here): AeroTitleBar is built on `rememberAeroWindowChrome`, instead of adding a separate showcase window with a non-AeroTitleBar header. Reasons: (1) the API then carries the full verification weight of the phase — every VER-11 check on the main and narrow windows, the `-Paero.nativeChrome=false` RED control and both VER-12 passes run through it — rather than living as a second native path proven only by a few extra checks; (2) it adds no extra minutes to the maintainer's hands-off session; (3) generality beyond AeroTitleBar's layout is locked headlessly in Plan 13 (a custom header with two caption areas and a left-hand maximize button publishes the right rects and classifies correctly).
Output: public API commit, AeroTitleBar refactor commit, live-proof notes.
</objective>
