## Spacing Scale

This is a two-component, fixed-size phase, not a page layout — the "scale" below is the
locked set of dp values these two buttons use. **All are LOCKED unchanged from the current
implementation per the milestone's own out-of-scope rule** ("no default size/corner-radius
creep beyond necessary," guarded by VER-03) — this phase changes *paint*, not *layout*.

| Token | Value | Usage |
|-------|-------|-------|
| Filled height | 30.dp | `AeroButton` fixed height — LOCKED unchanged |
| Outlined height | 28.dp | `AeroOutlinedButton` fixed height — LOCKED unchanged |
| Corner radius | 4.dp | Both buttons' `RoundedCornerShape` **and** the `cornerRadius` passed into `aeroSurface()` / `aeroGlowRing()` / `AeroSurfaceStyle`. LOCKED unchanged — do **not** fall through to `AeroSurfaceStyle.rest()`'s own `cornerRadius = 8.dp` default parameter; pass `cornerRadius = 4.dp` explicitly at every call site. |
| Filled horizontal padding | 12.dp | `AeroButton` `contentPadding` — LOCKED unchanged |
| Outlined horizontal padding | 10.dp | `AeroOutlinedButton` `contentPadding` — LOCKED unchanged |
| Vertical padding (both) | 2.dp | LOCKED unchanged — a declared exception to a 4pt grid, inherited from the existing shipped values; do not "round up" to 4.dp, that would grow the locked heights above |
| Bevel / rim stroke width | 1.dp | Inherited from `drawAeroSurfaceCore` (PRIM-05) — not a button-level choice, do not override |
| Glow-ring inner stroke | 1.5.dp | Inherited from `aeroGlowRing`'s `GLOW_RING_INNER_STROKE` constant |
| Glow-ring bloom stroke / step | 2.dp / 2.5.dp | Inherited from `aeroGlowRing`'s `GLOW_RING_BLOOM_STROKE`/`GLOW_RING_BLOOM_STEP` constants |

Exceptions: the 2.dp vertical padding and the primitive's own sub-integer stroke widths
(1.5.dp / 2.5.dp) are pre-existing/inherited, not newly introduced by this phase — listed here
for completeness, not as something to "fix."

## Color

Framing note: these two components are fixed-size interactive controls, not a page — the
Dominant/Secondary/Accent rows below are reinterpreted at the *component* level (per-state
surface roles) rather than a page-level 60/30/10 split. Both buttons ultimately resolve their
`AeroSurfaceStyle` from `AeroOrnamentTokens.derive(AeroTheme.colors)` (or
`colors.ornamentOverride` when set) — never new hardcoded literals.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (rest fill) | `ornaments.fillSplitTop` / `fillSplitBottom` (`primary.lighten(0.18f)` / `primary.darken(0.12f)`) | The two-tone gradient fill body of `AeroButton` at rest (VBTN-01) |
| Secondary (gloss / rim) | `ornaments.glossHighlight` (`glassHighlight.lighten(0.15f)`), `ornaments.rimLight` (`glassBorder.lighten(0.10f)`) | Top gloss band + outer contour — deliberately **neutral-derived** (white/glass-family), not accent-tinted, so gloss/rim read as light hitting glass regardless of the button's own hue |
| Accent (10%) | `colors.primary` (via the ornament-derived fill/bevel/glow fields above) | Reserved for: the filled `AeroButton`'s fill/bevel/hover-glow **only** — never the outlined button's dominant tone (that stays faint per D-06), never any neutral panel/card in this phase |
| Destructive | not applicable | No destructive-action variant is in scope for VBTN-01..06 — see Copywriting Contract |

### Filled `AeroButton` — per-state contract

**Finding to confirm during planning:** `17-CONTEXT.md` D-01 states the filled button's style
is "not literally the neutral `AeroSurfaceStyle.rest(base)` default (which derives from neutral
glass ornament tokens)." Reading the *actual shipped* `AeroOrnamentTokens.derive()`
(`AeroOrnamentTokens.kt`), however: `fillSplitTop`, `fillSplitBottom`, `bevelLight`,
`bevelShadow`, and `hoverGlow` are **already** derived from `base.primary`, not from a neutral
token — only `glossHighlight` and `rimLight` are neutral-derived (correctly, per above). So
`AeroSurfaceStyle.rest(colors, cornerRadius = 4.dp)` **already satisfies** D-01's "accent
identity, not flat neutral" requirement, used as-is, with no bespoke override needed. This is
recorded here as a documented finding for the planner/checker to confirm against D-01's literal
wording — not a silent reinterpretation of the locked decision.

| State | Fill (`fillTop` / `fillBottom`) | Gloss (`glossAlpha` / `glossHeightFraction`) | Bevel (`bevelLight` / `bevelShadow`) | Rim (`rimColor` / `rimAlpha`) | Extra cue |
|-------|----------------------------------|-----------------------------------------------|----------------------------------------|-------------------------------|-----------|
| Rest | `ornaments.fillSplitTop` / `fillSplitBottom` | 0.32 / 0.32 (`AeroSurfaceStyle` defaults) | `ornaments.bevelLight` / `bevelShadow` | `ornaments.rimLight` / 0.6 | `AeroSurfaceStyle.rest(colors, cornerRadius = 4.dp)` used as-is |
| Hover | rest, each stop `.lighten(0.08f)` | unchanged (optional +0.05f as a secondary cue) | unchanged | unchanged | `Modifier.aeroGlowRing(active = hovered && enabled, glowColor = ornaments.hoverGlow, cornerRadius = 4.dp)` chained BEFORE `aeroSurface` (ordering rule) — D-03's "whole button lights up," not just an outer ring |
| Press | `fillTop`↔`fillBottom` **swapped**, `bevelLight`↔`bevelShadow` **swapped**, `glossAlpha = 0f` — reuses `drawAeroGroove`'s exact field-swap idiom (no new gradient code) | 0 | swapped (see fill) | unchanged | `innerShadow = Shadow(radius = 2.dp, color = Color.Black.copy(alpha = 0.35f), offset = DpOffset(0.dp, 1.dp))` via `AeroSurfaceStyle.innerShadow` (native, per Phase 16 D-02 precedent — confirm at three-theme review, gradient rim is the fallback); the old `graphicsLayer` `scale = 0.97f` is **removed** (D-02, explicit) |
| Focus (no hover) | rest, unchanged | rest, unchanged | rest, unchanged | rest, unchanged | `Modifier.aeroGlowRing(active = focused && enabled, glowColor = colors.borderSelected, cornerRadius = 4.dp)` chained BEFORE `aeroSurface` — deliberately a **different token** than hover's `ornaments.hoverGlow` so hover-only vs focus-only vs both-co-active read as distinguishable per-theme without inventing a new field (D-04) |
| Disabled | flatten: `fillTop = fillBottom = lerp(fillTop, fillBottom, 0.5f)` blended ~40% toward `colors.borderDefault` (desaturates toward neutral gray, doesn't just darken the accent) | `glossAlpha = 0`, `glossHeightFraction = 0` | `bevelLight = bevelShadow = flatFill.darken(0.05f)` (collapsed to one tone — no light/shadow split reads as "dead") | `rimAlpha × 0.5` | Replaces the old uniform `alpha = 0.4f` — the geometry itself must flatten (D-05), not merely fade; label text alpha may still dim separately for legibility |

Both hover's `aeroGlowRing(...)` and focus's `aeroGlowRing(...)` chain independently before
`aeroSurface(...)` — e.g. `Modifier.aeroGlowRing(focus…).aeroGlowRing(hover…).aeroSurface(…)` —
so both bloom together when co-active, never overwriting one another.

### Outlined `AeroOutlinedButton` — per-state contract

VBTN-06's non-drift guarantee is expressed as: **every state row above, transformed by one
fixed delta**, never a second independent painter.

| Field | Filled → Outlined transform |
|-------|------------------------------|
| `fillTop` / `fillBottom` | alpha × ~0.15 ("a whisper of gloss/gradient," D-06) |
| `glossAlpha` | 0.32 → ~0.15 |
| `rimAlpha` | 0.6 → ~0.85 (brighter Aero contour — the outlined identity leans on its rim, not its fill) |
| `bevelLight` / `bevelShadow` | unchanged (contour emphasis carries the depth cue instead of fill) |
| `cornerRadius` | unchanged, 4.dp |
| Height / padding | 28.dp / 10.dp horizontal — unchanged, per Spacing Scale above |

Hover / press / focus / disabled deltas from the filled table above apply identically on top of
this base transform (e.g. outlined-hover = outlined-rest with the same `.lighten(0.08f)` fill
bump + the same two chained `aeroGlowRing` calls). This is what makes VBTN-06's "cannot visually
drift" true by construction, not by convention.

### VBTN-03 — hover-overlay clipping, resolved by construction

The old bug (square-corner bleed) was a literal `drawWithContent { drawRect(buttonHover) }`
full-bleed rectangle drawn *outside* the M3 container's own clip. That code path is **deleted
entirely**, not patched. In the new implementation:
- the fill-brighten hover cue is one of `drawAeroSurfaceCore`'s own round-rect draws, already
  inside `aeroSurface()`'s outermost `.clip(shape)` (PRIM-12) — it cannot bleed past the corner
  radius;
- the glow-ring bloom is *intentionally* unclipped and drawn outside the shape's layout bounds
  by design (PRIM-06) — that is the correct "glow" look, not the VBTN-03 bug, and must stay
  outside any clip per `aeroGlowRing`'s own usage contract (glow BEFORE surface in the modifier
  chain).

## UI Considerations

Applicable state considerations resolved: 1 covered, 0 backstop, 0 unresolved.

Only `long-text` applies to this phase's element kind (`interactive-control`) per the taxonomy's
relevance filter — `empty`/`loading`/`error`/`populated`/`partial`/`overflow`/`zero-one-many`

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| long-text | `AeroButton` / `AeroOutlinedButton` label (interactive-control) | ✅ covered | Button label renders single-line: `maxLines = 1`, `overflow = TextOverflow.Ellipsis`.
