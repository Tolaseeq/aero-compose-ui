# Phase 19 — UI Design Contract: Selectors + Lists

> Visual and interaction contract for `AeroSwitch`, `AeroSegmentedControl`, and `AeroListItem`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker. Almost entirely pre-populated from
> `19-CONTEXT.md` (D-01..D-13), the shipped Phase 16 primitives layer, the Phase 17 button
> resolver/transform precedent, and the Phase 18 slider thumb-state precedent — this phase asked
> the user nothing new. Every open slot below is Claude's-discretion territory already scoped by
> CONTEXT.md (pill geometry, recessed-segment color, exact gloss/groove magnitudes, hover-vs-focus
> differentiation), resolved here to a concrete, implementable default per the user's own
> instruction to "do as you know, corrections happen on execution" (19-DISCUSSION-LOG.md).

## Color

Framing note, same as Phases 17/18: these are fixed-geometry interactive controls, not a page —
Dominant/Secondary/Accent are reinterpreted at the *per-state, per-region* level. All three
components resolve style from `AeroOrnamentTokens.derive(AeroTheme.colors)` (or
`colors.ornamentOverride` when set), `AeroSurfaceStyle.rest()`/`neutralRest()`, or
`AeroTheme.colors`' own tokens directly — never new hardcoded literals, and every gradient fade
targets `baseColor.copy(alpha = 0f)` (PRIM-14), never `Color.Transparent`. Both currently-shipped
`Color.Transparent` uses (`AeroSegmentedControl.kt:59`, `AeroListItem.kt:63`) are removed by this
phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (accent) | `AeroSurfaceStyle.rest(colors, cornerRadius = …)` — `ornaments.fillSplitTop`/`fillSplitBottom` (`primary.lighten(0.08f)`/`primary.darken(0.12f)`) | `AeroSwitch`'s checked track groove fill (D-01); `AeroSegmentedControl`'s unselected-segment rest base (D-08, mirrors `AeroButton` rest — see Finding below); the selected list-item pill's base before `hoverLighten()` composes on top |
| Secondary (neutral thumb / groove / gloss-rim) | `AeroSurfaceStyle.neutralRest(colors, cornerRadius = …)` (Phase 18 factory) — `glassHighlight.lighten(0.12f)`/`glassSurface.darken(0.06f)` fill, `ornaments.glossHighlight`/`rimLight` gloss/rim | `AeroSwitch`'s thumb (always neutral, D-01) and its off-state groove (D-02, same geometry as on-state, only fill color animates) |
| Accent (10%) | `colors.primary` (only reachable via the Dominant row's ornament-derived fields) | Reserved for: `AeroSwitch`'s checked-groove fill ONLY (never the thumb — D-01); `AeroSegmentedControl`'s recessed-segment identity IF the review picks accent-recessed (Claude's discretion, resolved below); the selected `AeroListItem` pill's base fill |
| Destructive | not applicable | No destructive-action variant in scope for VSEL/VLST |

### Finding to confirm during planning — `AeroSegmentedControl` needs a raised-glass base, `AeroSwitch` needs its off-groove to stay neutral

Both findings mirror Phases 17/18's own "confirm the actual token derivation, don't assume"
discipline:

- **`AeroSegmentedControl` unselected segments (D-08):** `AeroSurfaceStyle.rest(colors,
  cornerRadius = 4.dp)` — the same call `resolveButtonStyle`'s `rest` starts from — already
  supplies the raised, accent-lightweight glass base needed for "a strip of buttons." No fill
  override is needed unlike `AeroButtonSurface`'s own `FILLED_FILL_TOP_DARKEN`/`FILLED_FILL_BOTTOM_DARKEN`
  override (that darkening exists specifically for legible white text on a *fully accent-filled*
  button; segments here are the *unselected* state and should read lighter/less saturated than a
  filled button, closer to `rest()`'s own ornament-derived fill, so segment text — which is
  `onSurface`/`primary`-colored, never white — stays legible without an override).
- **`AeroSwitch`'s off-state groove (D-02):** stays `AeroSurfaceStyle.neutralRest(colors,
  cornerRadius = 9.dp)` (half of 18.dp — the pill radius) in BOTH checked and unchecked states —
  only the checked state additionally recolors the fill toward `AeroSurfaceStyle.rest(colors,
  cornerRadius = 9.dp)`'s accent stops. Implementation note: since `AeroSurfaceStyle` fields are
  independently swappable via `.copy()`, the cleanest resolver shape is `neutralRest(...).copy(fillTop
  = lerp(neutralFill.fillTop, accentFill.fillTop, checkedProgress), fillBottom = lerp(...))` driven
  by the existing `animateColorAsState`-equivalent progress float, so only the fill stops animate
  (D-02's "one moving part") while gloss/bevel/rim geometry is shared and untouched.

### `AeroSwitch` — per-state contract

| State | Groove fill | Groove gloss/bevel/rim | Thumb fill | Thumb gloss | Extra cue |
|-------|-------------|------------------------|-------------|--------------|-----------|
| Rest, unchecked | `neutralRest(colors, cornerRadius = 9.dp)` fill stops, passed through `drawAeroGroove`'s own fill/bevel swap | `drawAeroGroove` applies its own recess treatment (gloss off, inner-shadow cue) — unchanged from the primitive's default | `neutralRest(colors, cornerRadius = 7.dp)` (14.dp thumb → 7.dp radius) via `aeroThumbSurface` | `AeroSurfaceStyle` default `glossAlpha`/`glossHeightFraction` (0.22/0.32) | Thumb at x = 2.dp |
| Rest, checked | Groove fill stops animated (150ms `tween`, D-07) from `neutralRest`'s stops toward `rest(colors, cornerRadius = 9.dp)`'s accent stops (D-01) — same recess/gloss-off/inner-shadow-cue geometry, only color changes (D-02) | unchanged geometry | `neutralRest(colors, cornerRadius = 7.dp)` — thumb stays neutral regardless of checked state (D-01) | unchanged | Thumb at x = 20.dp |
| Hover | groove fill unchanged from checked/unchecked resolution above | `Modifier.aeroGlowRing(active = hovered && enabled, glowColor = AeroOrnamentTokens.derive(colors).hoverGlow, cornerRadius = 9.dp)` on the whole track `Box` (D-06 — hot zone, where `toggleable` lives) | `neutralRest(...).hoverLighten()` on the thumb (D-06's "plus thumb lightening") | — | Glow ring chained BEFORE `aeroGroove` per the load-bearing ordering rule (`aeroGlowRing` before any `.clip()`-applying primitive — `AeroSurfacePrimitives.kt` KDoc) |
| Press | groove fill unchanged | no additional groove cue | `neutralRest(...).copy(glossAlpha = glossAlpha + PRESSED_GLOSS_BOOST)` — mirrors `resolveSliderThumbStyle`'s exact "stays raised, brighter gloss" idiom (D-05), reusing the `AeroSlider.kt` model, NOT `pressedRecess` | brighter gloss per above | Thumb stays raised, drawn on top of/outside the track's clip (D-03) — its shadow/glow ring are not clipped by the 18dp-tall track |
| Focus (no hover) | groove fill unchanged | `aeroGlowRing(active = focused && enabled, glowColor = colors.borderSelected, cornerRadius = 9.dp)` on the whole track — persistent, distinct token from hover's `hoverGlow` (D-06, mirrors Phase 17 D-04) | unchanged | — | `Modifier.toggleable(role = Role.Switch)` already supplies focusability + Space/Enter (no new semantics work needed) |
| Disabled | `neutralRest(...).flattenDisabled(colors)` / checked-accent equivalent flattened | flattened (gloss off, single bevel tone, rim halved) | `neutralRest(colors, ...).flattenDisabled(colors)` | flattened | Replaces the old uniform `alpha = 0.4f` (`AeroSwitch.kt:56`) — geometry itself flattens, not merely fades |

Thumb layering note (D-03): the thumb's `Box` (containing its own `aeroGlowRing` + `aeroThumbSurface`
chain) is a sibling drawn AFTER the groove `Box` inside the parent, unclipped by the groove's own
`.clip(shape)` — same pattern as `AeroSlider`'s thumb slot sitting outside the M3 track's bounds.

### `AeroSegmentedControl` — per-state contract

| State | Unselected segment | Selected segment | Extra cue |
|-------|---------------------|--------------------|-----------|
| Rest | `AeroSurfaceStyle.rest(colors, cornerRadius = 4.dp)` — raised glass, "strip of buttons" (D-08) | `rest(colors, cornerRadius = 4.dp).pressedRecess(PRESSED_INNER_SHADOW)` — imported verbatim from `AeroButtonSurface.kt` cross-package (D-08, VSEL-03) | Base composition resolved BEFORE hover/focus per-segment transforms compose on top |
| Hover (per segment) | `.hoverLighten()` on the segment's own resolved base (unselected or selected) | same `.hoverLighten()` composed on top of the recessed base — hover and selection combine, mirroring `AeroListItem`'s D-11 composition shape | In-bounds only (D-10): `hoverLighten` on the fill, no `aeroGlowRing` — the segment sits flush inside the outer `Row` + `.clip(shape)`, an outer bloom would be sliced by the frame and bleed onto neighbours |
| Press (per segment, before `onSelect` commits) | `.pressedRecess(PRESSED_INNER_SHADOW)` momentarily, same as `resolveButtonStyle`'s press branch | already recessed; press reads as a no-op visually (already at max depth) — acceptable, matches "you can't press a segment deeper than selected" | — |
| Focus (per segment) | inner rim / inner glow within the segment's own bounds (D-10) — concretely: a second inset `drawRoundRect` stroke using `colors.borderSelected` at the segment's own corner radius, drawn as part of the segment's own paint (not `aeroGlowRing`, which is outer-bloom-only) | same inner rim, layered on top of the recessed base | `Modifier.selectable(selected, role = Role.RadioButton, interactionSource = ..., onClick = { onSelect(opt) })` supplies focusability + Space/Enter natively (D-09) — replaces the bare `.clickable` |
| Disabled | `.flattenDisabled(colors)` on the unselected base | `.flattenDisabled(colors)` on the recessed base (recess geometry still visible, just dead-toned) | Replaces the old uniform `alpha = 0.4f` (`AeroSegmentedControl.kt:50`) |

**Recessed segment's color — Claude's discretion, resolved:** accent-recessed glass (`rest(colors,
...).pressedRecess(...)`, i.e. the selected segment's base IS the accent `rest` style before the
recess transform inverts it) — the literal "pressed `AeroButton`" reuse D-08/VSEL-03 call for, with
double signal (depth + color). Text color on the selected segment must switch to a light/neutral
tone (`colors.surface` or `colors.onSurface` inverted, whichever reads legible against the
recessed-accent fill on all three themes — verify at three-theme review per D-01/16 D-01
discipline) rather than staying `colors.primary`, since `colors.primary`-on-`colors.primary`-derived-fill
would be illegible. Unselected segment text stays `colors.onSurface` (unchanged).

**Segment separators (D-08/D-10 resolution):** dropped. Once every segment has its own raised (rest)
or recessed (pressedRecess) contour via `aeroSurface`'s own bevel+rim, the 1.dp `borderDefault@0.5f`
separator `Box` (`AeroSegmentedControl.kt:87-93`) is redundant — each segment's own contour supplies
the visual break, matching the literal Win7 toolbar idiom (adjacent raised buttons need no separator
line between them).

### `AeroListItem` — per-state contract

**Selection/hover pill geometry — Claude's discretion, resolved:** vertical-inset, full-width pill
(2.dp top/bottom inset, 0.dp horizontal inset, 6.dp corner radius) — suits the showcase's list
demos, which sit inside an already-padded panel (Win7 Explorer full-width row selection, not the
inset-floating-pill idiom). If the three-theme review finds the full-width variant reads too
flat against a panel's own edge, the four-side inset variant (e.g. 2.dp all sides) is the documented
fallback — either is CONTEXT.md-acceptable, this is the starting default.

| State | Style | Notes |
|-------|-------|-------|
| Rest, unselected | no pill drawn (no `aeroSurface` call) | Unchanged from current "no background" rest look |
| Rest, selected | `AeroSurfaceStyle.rest(colors, cornerRadius = 6.dp).copy(fillTop = fillTop.copy(alpha = fillTop.alpha * 0.5f), fillBottom = fillBottom.copy(alpha = ...))` — i.e. accent `rest()` at reduced opacity (mirrors the current `primary.copy(alpha = 0.2f)` intent but now gradient+gloss+rim, clipped to the pill shape via `Modifier.aeroSurface(style, RoundedCornerShape(6.dp))` on an inset `Box` (VLST-01) | Full gradient+gloss+rim pill, no longer the unclipped full-bleed flat `.background()` (D-12) |
| Hover, unselected | `AeroSurfaceStyle.neutralRest(colors, cornerRadius = 6.dp).hoverLighten()` drawn in the same pill shape/inset as the selected pill (D-12 — one shape, two style states) | Replaces `colors.buttonHover` flat fill; the pill draws only when `hovered && enabled` |
| Hover, selected | selected style (Rest-selected row above) transformed by `.hoverLighten()` on top — base resolves from `selected` FIRST, then `hoverLighten()` composes (D-11) | This is the structural fix for VLST-02: there is no `when` branch where hover is suppressed by selection — hovering a selected row is strictly brighter than resting-selected, never flatter |
| Focus (row has `onClick != null`) | inner rim / brightened pill contour within the row's own bounds (D-13) — concretely: an inset `drawRoundRect` stroke at `colors.borderSelected`, alpha ~0.8, drawn as part of the pill's own paint region (reuses the pill's inset/shape even on an unselected+unhovered row, where the pill background itself is otherwise not drawn) | No outer `aeroGlowRing` — list rows live inside scrolling/clipping containers where an outer bloom would be sliced (D-13, mirrors D-10's reasoning). A display-only row (`onClick == null`) gains no focus stop — `Modifier.clickable` is what supplies focusability today, so no `onClick` means no focus target, unchanged |
| Disabled | `.flattenDisabled(colors)` applied to whichever base (selected/unselected) would otherwise resolve | Replaces the old uniform `alpha = 0.4f` (`AeroListItem.kt:80`) |

Composition order, structurally (D-11, the anti-`when`-branch fix):
```
val base = if (selected) selectedPillStyle else null  // null = no pill drawn
val resolved = if (hovered && enabled) (base ?: neutralHoverStyle).hoverLighten() else base
```
`resolved` (nullable) drives whether/how the pill `Modifier.aeroSurface(...)` is applied — never a
three-way `when { selected -> ...; hovered -> ...; else -> ... }` color pick (the exact anti-pattern
at `AeroListItem.kt:60-64` today).

## UI Considerations

Probe classified three interactive-control surfaces: **E1** `AeroSwitch` (binary toggle), **E2**
`AeroSegmentedControl` (single-select group of N segments), **E3** `AeroListItem` (single row
within a caller-assembled list/collection). 8 categories probed against these three elements.
**2 covered, 1 backstop, 5 dismissed, 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| populated | E1, E2 | ✅ covered | Every value of a binary switch / every option in a segmented group renders through the same per-state style resolution table above — there is no separate "has data" vs "no data" branch for either bounded-choice control |
| zero-one-many | E3 `AeroListItem` inside a caller-assembled list | ✅ covered | `AeroListItem` itself is a single-row primitive with no internal collection concept — "zero/one/many rows" is the CALLER's `LazyColumn`/`Column` composition concern, explicitly out of this phase's per-component boundary (mirrors Phase 17's button-as-atomic-control framing). The row's own selected/hovered/focused resolution (Color § table above) is identical regardless of how many sibling rows exist |
| overflow | E2 `AeroSegmentedControl` long segment labels | 🧪 backstop | **Statement:** segment labels are single-line `Text` with no explicit `maxLines`/`overflow` today (`AeroSegmentedControl.kt:78-82`) — unlike `AeroButton`'s VBTN-03 fix (Phase 17), this phase's scope is VSEL-03/VSEL-04 (recess + hover/focus), not label truncation, and CONTEXT.md's boundary does not call out label overflow as in-scope. A caller supplying a long segment label today would widen that segment (and the whole `Row`) rather than truncate — pre-existing behavior, not newly introduced or newly fixed by this phase. **Verification (backstop):** confirmed at the three-theme visual review that the restyle (raised/recessed fill) does not change this pre-existing width-grows-with-label behavior — if the reviewer judges it should also gain `maxLines = 1` + `TextOverflow.Ellipsis` to match VBTN-03's precedent, that is a scope addition to flag during planning, not assumed here |
| empty | E1, E2, E3 | dismissed | No data-collection empty-state concept applies to a binary toggle, a fixed-option group, or a single list row — confirmed against the Copywriting Contract's empty-state rows (marked not applicable) |
| loading | E1, E2, E3 | dismissed | No async/busy state in scope for any of the three components (mirrors Phase 17's dismissal) |
| error | E1, E2, E3 | dismissed | No error/failure rendering in scope; `enabled = false` is the only negative state (Copywriting Contract, Color § Disabled) |
| partial | E1, E2, E3 | dismissed | No multi-field/partial-data concept — a switch is fully on/off, a segmented control has exactly one fully-selected option, a list row carries fixed caller-supplied text/leading/trailing slots |
| long-text | E3 `AeroListItem` primary/secondary text | dismissed | Unchanged from shipped — no `maxLines`/`overflow` handling exists today and none is added; the row's fixed 36.dp height with `Row`/`Column` layout means long text already wraps or overflows exactly as it did pre-restyle, and CONTEXT.md's boundary does not call this out as in-scope (unlike `AeroButton`'s VBTN-03, which explicitly listed a long-text fix) |
