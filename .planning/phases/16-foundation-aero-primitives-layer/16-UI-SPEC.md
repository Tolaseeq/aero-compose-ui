## Spacing Scale

This phase does **not** introduce a page-layout spacing scale (there is no page in scope — no
forms, no data views). Two distinct spacing concerns apply instead:

### 1. New Primitives showcase gallery layout (D-04) — standard 8-point scale

| Token | Value | Usage in the gallery |
|-------|-------|----------------------|
| xs | 4px | Icon/gap accents inside a demo card |
| sm | 8px | Caption-to-demo gap (matches `FoundationSection`'s existing `DemoBox` pattern: `Arrangement.spacedBy(8.dp)`) |
| md | 16px | Gap between demo cards in a row/grid (matches existing `FoundationSection` `Row` gap) |
| lg | 24px | Gallery section outer padding (matches existing `FoundationSection`'s `.glassPanel().padding(24.dp)` pattern) |
| xl | 32px | Gap between primitive groups (surface / glow-ring / thumb / groove / gloss / shadow) |
| 2xl | 48px | Not used this phase (reserved, no major section break needed inside one gallery) |
| 3xl | 64px | Not used this phase |

### 2. Existing component geometry — LOCKED, this phase must not alter (VER-03 carries forward)

These are **not** a spacing scale to design against — they are frozen intrinsic sizes on the
eight Phase 17–19 target components that this phase's primitives must fit *inside*, never expand:

| Element | Locked value | Source |
|---------|-------------|--------|
| `AeroButton` height | 30.dp | `AeroButton.kt:50` |
| `AeroButton`/`glassSurface` corner radius | 4.dp (button) / 8.dp (surface/card default) | `AeroButton.kt:91`, `GlassModifiers.kt:27,55,81` |
| `AeroSwitch` track | 36×18.dp | STATE.md Pitfall 7 |
| `AeroListItem` row height | 36.dp | STATE.md Pitfall 7 |
| Border/stroke width | 1.dp (glass border), 2.dp (selected-state border) | `GlassModifiers.kt:44,102`; `AeroButton.kt:66` |

**Exceptions:** New ornamentation (gloss band, bevel/rim stroke thickness, glow-ring stroke width)
must render either inset within these locked sizes or drawn outside layout bounds via unclipped
`drawBehind` — never by adding dp to a component's declared size (Pitfall 7). Exact gloss-band
fraction is Claude's discretion within the D-01-locked ~30–35%-of-height band; not a hard literal.

## Color

`aero-compose-ui` ships three interchangeable theme presets (`AeroBlue`, `AeroDark`, `Classic`) —
every rule below applies identically across all three (PRIM-16's three-theme-proof mandate), not
just one fixed palette.

| Role | Token(s) | Usage |
|------|----------|-------|
| Dominant (60%) | `background`, `surface` (e.g. AeroBlue `0xFF0D1B2A`/`0xCC1A3A5C`; AeroDark `0xFF0A0A1A`/`0xCC1A1A2E`; Classic `0xFF1E1E1E`/`0xFF2D2D2D`) | App/window background, base surface under every glass layer |
| Secondary (30%) | `cardBackground`, `panelBackground`, `glassSurface` | Cards, panels, the mid-level glass surface fill (`Modifier.glassSurface`) |
| Accent (10%) | `primary` (existing) **+ new `AeroOrnamentTokens`** (`glossHighlight`, `bevelLight`, `bevelShadow`, `rimLight`, `hoverGlow`, `grooveShadow`, `fillSplitTop`, `fillSplitBottom` — PRIM-02, algorithmically `derive()`d via `Color.lighten()`/`darken()`, never new raw literals) | See "Accent reserved for" below |
| Destructive | `error` (e.g. `0xFFEF5350` across all three themes) | `closeButtonHover` on window chrome; unchanged, not touched this phase |

**Accent reserved for (explicit list — never "all interactive elements"):**
- Gloss highlight band on a component's own surface (`drawAeroSurfaceCore`'s gloss layer, PRIM-04/05)
- Bevel light/shadow edges (inner bevel rim, PRIM-04)
- Rim light stroke (outer contour highlight, PRIM-04)
- Hover/focus glow ring (`Modifier.aeroGlowRing`, PRIM-06) — gated to active interaction states only, never a persistent `rememberInfiniteTransition`
- Groove shadow inside a recessed track (PRIM-08)
- Raised-thumb highlight (`aeroThumbSurface`/`drawAeroThumb`, PRIM-07)
- `borderSelected` (existing token, unchanged) — selected/focused component outline

**Never** as a flat full-surface fill on any of the eight downstream components — this is the
exact PRIM-14 guard: every new gradient must fade to `baseColor.copy(alpha = 0f)`, never a
hardcoded `Color.Transparent`, so `Classic`'s opaque tokens degrade to "less of itself" instead of
rendering a flat colored block (confirmed root cause in `AeroColorScheme.kt:91-115` vs `:39-89`).

## UI Considerations

> Populated by the ui-phase UI-consideration probe. This phase's only user-facing surface is the
> permanent Primitives showcase gallery (D-04) — a fixed, compile-time set of primitive demos,
> not a data-bound view. Categories below are filtered to what a design-system-primitives gallery
> can meaningfully raise (per the probe's relevance filter: element kinds present here are
> `list-collection` — the gallery grid — and `interactive-control` — individual hover/press/focus
> demo boxes and the M3 Slider spike; `static-content` — captions).

Applicable state considerations resolved: 2 covered, 1 backstop, 0 unresolved; 5 dismissed (not applicable, reason given — no `unclassified` candidates).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Primitives gallery (list-collection) | dismissed | Fixed compile-time set of 6 primitive groups (surface/glow-ring/thumb/groove/gloss/shadow) — never dynamically empty; no data source to be absent |
| loading | Primitives gallery (list-collection) | dismissed | Everything renders synchronously at composition time — no async data fetch exists in this phase |
| error | Primitives gallery (list-collection) | dismissed | No data load/submit surface exists in this phase's scope |
| populated | Primitives gallery (list-collection) | ✅ covered | The gallery's happy-path view shows all 6 primitive groups × three themes (AeroBlue/AeroDark/Classic) × applicable states (default/hover/press/focus/disabled) legibly in one scrollable section, matching `FoundationSection`'s existing Row-of-`DemoBox` layout pattern extended to 6 groups instead of 3 |
| partial | Primitives gallery (list-collection) | dismissed | No partial-data concept applies — each primitive group either fully renders or doesn't compile |
| overflow | Primitives gallery layout (list-collection / static-content) | 🧪 backstop | 6 primitive groups × up to 5 states × 3 themes is a larger grid than `FoundationSection`'s original 3 boxes; gallery section must be vertically scrollable (inherits the existing showcase's outer `Column`/scroll-container convention) so the grid never clips — verify at PRIM-16's three-theme gallery review, not assumed |
| zero-one-many | Primitives gallery (list-collection) | dismissed | Fixed count of 6 primitive groups, never 0/1/many dynamically |
| long-text | Demo captions, state labels (static-content) | ✅ covered | All captions are short fixed English identifiers (primitive/API names, one-word state labels) matching the existing `"glassEffect"`/`"glassPanel"`/`"glassSurface"` precedent length — no wrap/truncation handling required, none introduced |
