# Requirements: aero-compose-ui — v3.1 Dependency Refresh + Hot Reload MCP

**Defined:** 2026-09-23
**Core Value:** Разработчик подключает одну зависимость и получает полный набор Aero-styled компонентов с тремя темами, кастомной шапкой окна, типизированным набором иконок и демо-витриной — без необходимости реализовывать стиль или искать совместимый icon pack самостоятельно.

**Milestone goal:** Принудительно перевести проект на последние стабильные версии зависимостей и тулчейна, доказать, что ничего не сломалось, и выпустить `3.1.0` на JitPack. Одновременно поставить Compose Hot Reload с MCP-сервером, через который агент сам смотрит и кликает работающую витрину, и доказать, что этот способ отладки не мешает мейнтейнеру пользоваться компьютером.

**Research:** `.planning/research/SUMMARY.md` (+ STACK / FEATURES / ARCHITECTURE / PITFALLS) и `.planning/research/MCP-HOWTO.md` — инструкция, проверенная мейнтейнером на практике. При расхождении с исследованием побеждает она.

**Стоп-правило (для всех фаз):** если обновление Kotlin / Compose Multiplatform / Hot Reload или установка JBR требует большего, чем смена версии плюс механические правки, продиктованные новым API, работа останавливается и вопрос уходит мейнтейнеру. То же — если MCP двигает настоящий курсор или забирает фокус ввода. Обходных путей не ищем.

## v3.1 Requirements

### Baseline (BASE)

Снимается ДО любых изменений версий: без эталона «до» дрейф после обновления не с чем сравнить, а MCP на Compose 1.11.1 не работает (`list_windows` пуст).

- [x] **BASE-01**: Витрину можно открыть сразу на выбранной теме и выбранном разделе без мыши — параметр запуска рядом с существующим `-Paero.scheme` — и раздел виден целиком. Изменение только в `:showcase`, `:library` не трогается
- [x] **BASE-02**: В репозитории лежит помощник захвата окна. Он снимает содержимое окна витрины через WinAPI `PrintWindow(hwnd, hdc, 2)`, в том числе когда окно перекрыто другими окнами; свёрнутое окно разворачивает без перехвата фокуса (`ShowWindow(h, 4)`) и держит внизу z-порядка (`SetWindowPos(h, HWND_BOTTOM, …, 0x13)`); после захвата сверяет пару пикселей с фоном приложения. Настоящий курсор и фокус ввода не трогает
- [x] **BASE-03**: Повторный захват одного и того же состояния даёт тот же кадр, либо шумовые области (анимации, каретка, indeterminate-прогресс) измерены и перечислены. Иначе сравнение «до/после» не отличит дрейф от шума
- [x] **BASE-04**: Эталонные кадры всех разделов витрины × 3 темы (AeroBlue / AeroDark / Classic) сняты помощником BASE-02 на текущем тулчейне (Kotlin 2.4.10 / CMP 1.11.1) и сохранены вне `build/` с пометкой тулчейна
- [x] **BASE-05**: Набор Compose UI-тестов снимает в картинки hover, press, фокус с клавиатуры и перетаскивание — через `performMouseInput` / `performKeyInput` + `captureToImage`, без окна на экране и без системного ввода. Охват: интерактивные стеклянные компоненты v3.0 (`AeroButton`, `AeroOutlinedButton`, `AeroSwitch`, `AeroSegmentedControl`, `AeroSlider`, `AeroRangeSlider`, `AeroListItem`) и перетаскиваемые (`AeroSplitPane`, `AeroPanelGroup`, ресайз колонок `AeroDataTable`), в трёх темах. Кадры первого прогона на старом тулчейне — эталон, хранятся вне `build/`. Первым шагом доказывается, что `captureToImage` работает в десктопном `runComposeUiTest`; если нет — стоп и вопрос

### Toolchain + Dependencies (TOOL)

Каждый шаг изолирован и проверяется полным тестовым прогоном до следующего: регрессию нужно уметь отнести к одной причине (урок v3.0).

- [x] **TOOL-09**: Gradle wrapper 9.7.1, чистая сборка проходит. Устаревший адрес репозитория JetBrains (`maven.pkg.jetbrains.space/...`, сейчас отвечает перенаправлением) убран из `settings.gradle.kts` — проверено сборкой с `--refresh-dependencies`
- [x] **TOOL-10**: JDK 21 везде: `jvmToolchain(21)` в `:library` и `:showcase`; опубликованный байт-код — class-file 65, в Gradle module metadata `org.gradle.jvm.version = 21`
- [x] **TOOL-11**: Kotlin 2.4.20 + Compose Multiplatform 1.12.0. Kotlin 2.4.20 официально поддерживает Gradle до 9.7.0: предупреждения на 9.7.1 фиксируются, но поломкой не считаются, пока сборка и тесты зелёные
- [x] **TOOL-12**: Material3 остаётся на стабильной `1.9.0`. `dependencyInsight --dependency material3` на compile- и runtime-classpath `:library` и `:showcase` не показывает ни одной alpha — ни от Compose 1.12.0, ни (после HRM-01) от Hot Reload
- [x] **TOOL-13**: kotlinx-coroutines 1.11.0
- [x] **TOOL-14**: kotlinx-datetime — чистая 0.8.0, не `-0.6.x-compat`. Какие правки исходников пикеров нужны (`Clock` / `Instant`, `dayOfMonth` / `monthNumber`), решает компиляция, а не исследование: исследователи разошлись. Фактический итог записывается. Поведение пикеров не меняется, их тесты зелёные
- [x] **TOOL-15**: JUnit 6.1.3, jupiter и platform launcher выровнены
- [x] **TOOL-16**: Тестовый прогон исполняет ровно столько тестов, сколько на старом тулчейне непосредственно перед обновлением (467 на закрытии v3.0 плюс тесты BASE-05; число перемеряется, а не берётся из документов). Сверка числа доказана падающей: исключённый тестовый класс её валит (урок v2.0.3 — страж, не проверенный на красном, не страж)
- [x] **TOOL-17**: Витрина собирается и запускается на новом тулчейне

### Hot Reload + MCP (HRM)

Инструмент, а не цель вехи: через него агент сам смотрит и кликает витрину после обновления. Ставится по `.planning/research/MCP-HOWTO.md`.

- [x] **HRM-01**: Сразу после перехода на Compose 1.12.0 одним коммитом поставлены Compose Hot Reload 1.2.0 (версия явно в каталоге) и `.mcp.json` (`cmd /c .\gradlew.bat --no-daemon --quiet --console=plain hotMcpServer`) — только в `:showcase`. `:library` и её опубликованные POM / module metadata не меняются, Material3 по-прежнему 1.9.0 (`dependencyInsight`)
- [x] **HRM-02**: После перезапуска Claude Code сервер подключён и видит витрину, запущенную через `hotRun` на выбранной теме и разделе (`status`, `list_windows`, `get_semantic_tree`). Где подписи в дереве неоднозначны, в витрине добавлен `testTag`. Записано, подхватывает ли `reload` правку кода `:library` без перезапуска витрины
- [x] **HRM-03**: Агент сам замерил, что работа через MCP не мешает пользоваться компьютером: положение курсора (`GetCursorPos`) и активное окно (`GetForegroundWindow`) до и после захвата, чтения дерева и клика не меняются — в том числе при перекрытом и свёрнутом окне витрины. Итог — короткий факт в отчёте; серверный `take_screenshot` не используется

### Verification (VER)

- [x] **VER-07**: После обновления все разделы × 3 темы сняты тем же помощником BASE-02 и сравнены с эталоном BASE-04. Каждое расхождение вне шумовых областей BASE-03 либо объяснено с названной причиной, либо исправлено
- [x] **VER-08**: UI-тесты BASE-05 прогнаны на новом тулчейне, их кадры сравнены с эталоном; агент сам просмотрел hover, press, фокус и перетаскивание в трёх темах
- [x] **VER-09**: Всё, что не подтверждено ни живым окном, ни UI-тестами, вынесено отдельным списком «не подтверждено» и не выдаётся за пройденное. Сюда как минимум входят hover остальных ~40 компонентов, всплывающие части за рамкой окна, масштаб экрана 125% / 200% и поведение, не выраженное в семантике
- [x] **VER-10**: Мейнтейнер получает интерфейс на осмотр только после того, как агент завершил собственный обход и доволен результатом. Передача включает кадры, список объяснённых расхождений и список «не подтверждено»

## Out of Scope

| Feature | Reason |
|---------|--------|
| Новые компоненты, изменения публичного API | Веха — обновление зависимостей и инструмент отладки |
| Визуальные правки | Только починка дрейфа, вызванного самим обновлением |
| Долги v3.0 | Отдельная веха |
| Серверный `take_screenshot` | Снимает область экрана под окном, а не содержимое окна; захватывает чужие окна. Заменён на `PrintWindow` |
| Доставка наведения, клавиш и перетаскивания в живое окно (сообщения Windows, `java.awt.Robot`) | Выбор мейнтейнера: эти состояния проверяются UI-тестами, системный ввод и живое окно оператора не трогаются |
| foojay toolchain resolver | JBR 21 уже установлен и виден Gradle (`C:\Users\1\.jdks\jbr-21.0.9`); JitPack получает JDK из `jitpack.yml` |
| `androidx.lifecycle` 2.11.0 | Проект не использует lifecycle / ViewModel |
| Hot Reload 1.3.0-alpha, Material3 alpha | Только стабильные версии |
| Внешний scratch-потребитель как гейт релиза | Выбор мейнтейнера: тесты + обход витрины агентом |
| Совместимость с Java 17 и Compose < 1.12 у потребителей | Осознанный выбор: `3.1.0` поднимает порог, README это прямо называет |
| Пиксельный diff как автоматический pass/fail-гейт | Сравнение «до/после» — инструмент разбора расхождений агентом, а не автоматический вердикт (в v3.0 пиксельный гейт признан хрупким) |
