<objective>
Fix CR-01 — the raised, unselected segment fill is the unmodified accent-derived plate, so the on-surface label sits on top of a colour of nearly its own value and effectively disappears on AeroDark — by darkening the raised base the same way the filled button already darkens the identical fill, and by putting a value-level contrast guard underneath it so this regression class fails a test instead of only a human eye.

Purpose: `resolveSegmentStyle` builds its raised base from the shared rest preset unmodified. That preset resolves its fill stops from the ornament tokens, which derive them from the accent token by a light lighten and a light darken — a fully opaque, accent-derived plate. The label is the on-surface content token at full alpha in every state. On AeroDark those two colours measure 1.04:1. `AeroButtonSurface` diagnosed and fixed this exact failure mode two phases earlier for the exact same fill shape, and documented why; the segmented control consumes the preset unmodified and therefore reproduces the bug the button already solved. Its own darken constant is applied only to the already-recessed selected segment, never to the raised base.
Output: two named darken constants applied to the raised base, an anti-drift KDoc that describes what the resolver now actually returns, an updated from-scratch reconstruction in the styles suite, that suite widened to cover the scheme where the defect is worst, and a new contrast-ratio guard.
</objective>

<planner_finding>
**The arithmetic — and an honest conflict between the two things the developer asked for.**

The developer asked for two things that pull against each other: start from the filled button's own precedent (`0.20f` top / `0.36f` bottom), and gate the result with a contrast test at a minimum ratio of 3.0. The planner computed both before writing this plan. They do not meet.

Method: WCAG 2.x relative luminance, ratio `(L_lighter + 0.05) / (L_darker + 0.05)`. The method is calibrated — applied to the CURRENT unmodified fill it reproduces the review's own measured figure for AeroDark (1.04:1) exactly, so the numbers below are trustworthy as a starting estimate rather than a guess.

Contrast of the on-surface label token against the accent token darkened by `d`:

| scheme | accent | label | d = 0.20 (precedent top) | d = 0.36 (precedent bottom) | d = 0.42 | d = 0.45 |
|---|---|---|---|---|---|---|
| AeroDark | `#90CAF9` | `#CCCCCC` | **1.70** | **2.57** | 3.02 | 3.29 |
| AeroBlue | `#4FC3F7` | `#E0E0E0` | **2.35** | 3.49 | 4.10 | — |
| Classic | `#5C8ABF` | `#E0E0E0` | 3.98 | — | — | — |

So the precedent's own values are a large improvement over 1.04:1 but do **not** clear 3.0 for the top stop on AeroDark or AeroBlue. The reason is not that the button's fix was wrong — it is that the button's fix was calibrated for near-white button text, while this component is locked to the on-surface content token by the G3 fix and by a source guard.

The arithmetic points at approximately **0.45 top / 0.61 bottom** (preserving the precedent's ~0.16 gap between the two stops so the gradient keeps its direction and its relative shape). That is materially darker than a filled `AeroButton`, which is a real, visible consequence and exactly why plan 19-12's human checkpoint exists and why the magnitude is explicitly retunable there.

**The test is the arbiter, not this table.** Declare the constants, start at the precedent, run the guard, raise until every scheme passes at both ends of the selection axis, then stop. Record the values you landed on and the measured ratios in the SUMMARY. Do not silently accept a lower threshold to make the precedent fit.

**Why the darken must land on the base, not on the recessed style.** The recessed style is built by applying the imported pressed-recess transform to the raised base and then darkening the result by this component's own recess constant. That transform EXCHANGES the two fill stops. If the raised base is darkened first, the recessed style inherits the correction through the exchange, both segments move down together, and the pre-existing "recessed is strictly darker than raised" invariant is preserved because both sides scale by the same factor. If instead the darken were applied after the exchange, only the raised segments would move and the invariant would invert.

**Why the top stop is not always the one under the label.** At the unselected end the top stop is the lighter of the two, so it is the worst case. At the fully-selected end the exchange has already happened, so the BOTTOM stop is the lighter one. Asserting only the top stop would therefore leave the selected segment's worst case unguarded. The guard covers both stops at both ends — a strict superset of what was asked for, at no extra cost.

**Why AeroDark must join the styles suite.** The suite currently exercises AeroBlue and Classic only. AeroDark — the one scheme where the label was measurably invisible — has never been covered by a single value-level assertion in this file. That omission is a direct contributor to CR-01 shipping.
</planner_finding>
